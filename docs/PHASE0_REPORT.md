# Phase 0 — Data Feasibility Report

実施: 2026-11-14 12:25–12:55 JST / 実施者: Claude Code セッション
凡例: **[検証済]** = このセッションで実際に取得・処理・表示して確認した / **[未検証]** = 資料上は存在するが試していない / **[失敗]** = 試して使えなかった

## 1. 結論

**Jezero Crater のデルタ前縁(Skinner Ridge / Wildcat Ridge 周辺、約 1.3 × 1.2 km)を推奨する。**

決め手は 3 つ。

1. 調査地点が構造化データとして公開されている(試料名・岩種・採取日・座標・標高)。Gale 側には同等のレイヤーが無い。
2. 軌道データ(MRO)と地上データ(Mars 2020)が同じ座標系で実際に重なることを数値で確認できた(DTM とローバー標高の差: 平均 0.06 m / 標準偏差 0.13 m、129 点)。
3. ローバーの生画像から北基準のパノラマを再構成でき、軌道 DTM から計算した稜線がその画像の稜線と一致した。地図上の地点を現地視点の画像へ座標から投影できる(FIELD モードの中核になる)。

## 2. 公式課題の要件整理

課題文(2026-11-13 更新版)を取得して確認した。

- **求められていること**: 火星表面の地点またはルートについて、複数の NASA 科学ミッションのデータを重ねた統合ビューを作り、探査者が Marswalk を計画・実行する助けにする。
- **推奨(may / might / consider。必須ではない)**: 3 種類以上のデータ(光学・熱・分光・地形・地球物理・大気・放射線・化学など)、安全に関わる情報(放射線・宇宙天気)、宇宙服での移動性の考慮、障害物を避けるルートマップ、現地視点画像の組み込み、表示形態(居住区内ディスプレイ / タブレット / HUD)、ローバーや 2 人組での運用。
- **課題が指摘する既存ツールの限界**: Mars Trek や USGS 地質図は地域〜全球スケール向けで、1 回の船外活動が対象とする局所スケールには向いていない。→ Mission Lens の「局所・1 回の Marswalk」という焦点は課題文と一致する。
- **公式 Resources(5 件)**: Mars Trek / USGS-NASA Planetary Geologic Mapping Program / Curiosity の Mount Sharp 提案ルート / NASA Worldview / Perseverance Raw Images Gallery。

## 5. 検証結果

### 5.1 複数ミッションの位置合わせ **[検証済]**

- AOI 内の 129 ウェイポイントで、HiRISE DTM の標高とローバーの `elev_geoid` を比較: 差の平均 0.06 m、標準偏差 0.13 m、最小 −0.18 m、最大 0.70 m。
- 5 つの試料採取地点でも差は 0.3 m 以内。
- 正射画像に傾斜と走行経路を重ねると、急斜面の分類が崖線と一致し、経路は緩斜面(Hawksbill Gap)を通っている(`experiments/phase0/out/registration_check.jpg`)。
- 注意: ローバーの位置決め自体がこの HiRISE ベースマップを基準にしているため、これは完全に独立した検証ではない。こちらの処理(投影・切り出し)が正しいことの確認である。

### 5.2 生画像からのパノラマ再構成 **[検証済]**

- raw_images API は Navcam の各フレームに CAHVOR(E) カメラモデルとローバー姿勢(四元数)を付けている。特徴点マッチングなしで、各フレームを北基準の正距円筒画像へ再投影できた(4096×1365、約 12 秒)。
- カメラモデルはタイル単位で調整済み、座標系はローバー基準であることを数値で確認した。
- 検証: ローバー位置から HiRISE DTM で地形の稜線(方位ごとの最大仰角)を計算し、パノラマに重ねたところ、北側の崖と南側の開けた地平が一致した(`pano_dtm_horizon_check.jpg`)。近距離(10–20 m)の露頭では 1–2° 程度のずれがある。
- 地図座標から投影した Skinner Ridge のマーカー(22 m、方位 40°)は、画像内の層状露頭の位置に載った。
- 残る問題: 露出の異なるフレーム間に明暗の継ぎ目が残る(露出ごとのゲイン補正のみ実装)。仰角 +25° より上と一部の隙間は未撮影。ローバーの車体が写り込む。マスト回転による視差(約 0.3 m)で近距離の岩に段差が出る。

### 5.3 ブラウザでの統合表示 **[検証済(ヘッドレス)]**

- Three.js で DTM メッシュ(341×297 頂点)に正射画像を貼り、傾斜・陰影・THEMIS をシェーダーで重ね、経路と採取地点を載せた。2D / 3D / 地上視点の 3 状態を表示できた。
- 確認方法はヘッドレス Chrome の URL プリセットによるスクリーンショット 4 枚。**人の手によるマウス操作(ドラッグ・クリック・切り替えアニメーション)と描画速度は未確認。**

### 5.4 使えなかったもの **[失敗]**

- **ウェイポイントの公式パノラマモザイク**: `M20_waypoints.json` は全 708 点にパノラマのファイル名と方位・仰角範囲を持つが、画像本体(`Layers/mosaics/*.jpg`)は HTTP 403 で取得できない。パスの変形 8 通りも不可。→ 5.2 の自前再構成に切り替えた。
- **Trek の Jezero DTM タイル**: カタログには載っているが WMTS Capabilities が 404。→ USGS の GeoTIFF を直接読む方式にした。
- **WebFetch ツール**: 証明書エラーで全滅。`curl` で代替した。公式課題ページは Next.js の埋め込みデータから本文を抽出した。

## 6. 未検証・残リスク

- **分光(CRISM)**: 試していない。局所スケールで使える鉱物マップが短時間で作れるかは不明。代替として、現地の試料分析結果(岩種など)を地点データとして示す案がある。
- **USGS 地質図 SIM 3464**: 存在とサイズ(333 MB)のみ確認。1:75,000 なので 1.3 km の AOI では数ユニットしか入らない可能性が高い。
- **熱データの粗さ**: THEMIS は AOI 全体で 17×15 px。局所の判断材料にはならず、地域的な文脈としてしか示せない。
- **他地点のパノラマ**: Wildcat Ridge(sol 502)の 1 地点のみ。Skinner Ridge(sol 490 付近)や経路途中は未作成。地点ごとに使える Navcam シーケンスがあるかは都度確認が必要。
- **Mastcam-Z の再投影**: 未着手。同じ方式が使えるはずだが確認していない。
- **MEDA**: ファイル取得まで。地表温度・気温は calibrated 側にあり未取得。
- **傾斜の分類閾値(10 / 15 / 20°)**: こちらで仮に置いた値。NASA の EVA 基準ではない。根拠資料を当てるか、「例示」と明記し続ける必要がある。
- **オフライン動作**: 加工済みデータはローカルにあるが、会場ネットワークなしでの通し動作は未確認。

## 7. 推奨する技術構成

- **表示**: Web + Three.js(ビルドなしの ES Modules で開始。必要になったら Vite)。Unity は使わない。
- **データ**: Python(numpy / rasterio / Pillow)で事前に焼き、`assets/data/` に静的ファイルとして置く。実行時に NASA のサーバーへは問い合わせない(デモの安定と出典管理のため)。
- **XR**: 同じ Three.js コードから WebXR で Quest 3 に出す道がある **[未検証]**。Phase 4 の余力枠。

理由: Phase 0 の表示がこの構成で 30 分以内に動いた。データ加工が成果の半分を占めるので Python が要る。Unity に載せ替える利点が今のところ無い。

## 8. 設計上の発見(提案)

Phase 0 で最も強かったのは「地図上の地点が、実際の地上画像の中の正しい位置に出る」こと。これを Mission Lens の軸に据えることを提案する。

- **TRAIN → FIELD の遷移**: 3D 地図で地点を選ぶ → カメラが目線の高さまで降りる → 同じ方位の実画像パノラマへ切り替わる。地点マーカーと経路は両方に同じ座標から描かれる。
- **稜線の重ね描き**: 軌道 DTM 由来の稜線を地上画像に重ねる。位置合わせの証拠(Validity)であり、現地での方位確認の手がかりにもなる。
- **見通し判定**: DTM から「次の地点はここから見えるか / 地形の陰か」を計算して表示する(Phase 0 で実装済みの関数がある)。

## 9. 次に作る最小 UX プロトタイプ(提案)

**「1 地点の TRAIN → FIELD 往復」**

1. 3D 地図上に、仮想 Marswalk の 3–4 地点と徒歩ルートを表示(傾斜レイヤーつき)。
2. 地点を選ぶと、科学目標・その地点での作業(BASALT の活動フェーズ)・実試料の記録が出る。
3. 「現地へ」で目線まで降下し、実画像パノラマに切り替わる。次の地点への方位・距離・見通しを表示。
4. 作業を完了にすると、地図とタイムラインの両方が進む。

評価したいこと: 遷移が「同じ場所だ」と直感的に伝わるか / FIELD で情報が多すぎないか / 30–90 秒のデモの芯になるか。
