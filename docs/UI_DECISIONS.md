# UI/UX の判断記録

最終更新: 2026-11-15 02:55 JST / Claude Code

2026-11-14 の企画セッションの連絡により、これまでの UI/UX 案は確定要件を除いて参考扱いになり、設計は各開発セッションに任された。この文書は、重要な UI 案の状態(採用 / 検討中 / 見送り)と理由を残す。対象は Quest 3 の MR / VR の空間 UI。「擬似版」は `experiments/spatial/index.html`(デスクトップでの代役)を指す。もう一方の AI セッションの UI は見ていない。

**どれも人の手と実機では未確認。** 1〜11 は擬似版で、ヘッドレス Chrome での操作の自動確認(25 項目)と画面の目視まで。23 以降は Unity 版(`unity/Assets/MissionLens/`)で、Editor の Play をデスクトップ用のカメラで動かし、開始から終了までを通しで実行して画像で見たところまで。文字の大きさや置き場所は Quest での見かけの角度に換算して決めたが、実機では見ていない。

## 設計の軸

- **PLAN は机が画面、FIELD は景色が画面。** 部屋では両手と視野が空いていて読む時間がある。現地では手も目も地形に向いている。
- **データはメニューから選ぶものではなく、判断の場面に出るもの。** 「歩けるか」に傾斜、「なぜここか」に分光と試料記録、「何が見えるか」に実画像。
- **出どころは一目で分かるようにする。** NASA の観測 / NASA の記録 / こちらの計算 / 仮想の計画 / 模擬の記録。

## 採用(Quest 3 での最初の実行を受けて、2026-11-15 02:05)

ユーザーの実機での所見: パススルーは見えた。手のピンチで押せた。読める位置には出たが、**ボードが広すぎて遠い、模型を近く・大きく見たい**。遠くの文字は少しジャギる。手の表示はもっと手の形がよい。部屋の背景によっては見づらいので、完全 VR の部屋に切り替えられるとよい。

| # | 案 | 理由 |
|---|---|---|
| 41 | 机は「部屋に固定した 86×79 cm の台」で、その上の地図を手で動かす。片手のピンチで滑らせ、両手で伸縮・回転(1 : 1500 〜 1 : 200)。地形・ルート・目印は台の縁で切れ、側壁と台の高さは載っている範囲に追従する | 肝心の A・B・C が模型の奥に 15 cm ほどの範囲で固まっていて、小さく遠かった。地図を引き寄せて大きくできれば、机を大きくしなくて済む |
| 42 | 時間割で作業を選ぶと、その区間や地点が台の上に来る(「Follow tasks」。切れる)。「Whole route」で全体に戻る | 手で動かせない・動かさない人でも、説明の順に必要な場所が大きく出る。A → B の登りを選ぶと、1 : 200 で傾斜の色つきの区間と露頭が見える |
| 43 | ブリーフィングは「正面の壁」にまとめる: 内側へ向けた 2 枚のボード(左: 目標と理由、右: NASA の根拠)の下に時間割。目から約 1.3 m、横幅約 50°(以前は約 1.7 m 先に幅 2.2 m)。机は 20 cm 手前へ | 首を振らずに読める幅に。遠く大きく置くより、近く小さく置くほうが文字が安定する(ユーザーの所見と一致) |
| 44 | 凡例の札に、机そのものの操作をまとめる(Whole route、Follow tasks、Bring table here、Room)。北の矢印は地図の回転に合わせて回り、縮尺の棒は伸縮に合わせて切り替わる | 時間割は時間の操作、札は机と地図の操作、と役割を分けた |
| 45 | スタジオの部屋(暗い空間、格子の床、模型の下の台座)に切り替えられる。既定は実際の部屋(パススルー) | 背景が散らかっていると模型やボードが見づらい。デスクトップでは常にこの部屋 |

## 採用(Quest 3 での 2 回目の実行を受けて、2026-11-15 02:55)

ユーザーの所見(02:15 のビルド): 手が変わっていない。ボードはまだ見づらく、机の上に広げてあるくらいでよい。パススルーが消えて真っ暗。FIELD で天球画像の黒い部分が抜けている。地図の操作はもっと遊べる。パネルをタップするだけではつまらないので、宇宙飛行士のモチーフや、球をつかんで回すと変わるような操作を、実験的にいくつか入れて切り替えて試したい。

| # | 案 | 理由 |
|---|---|---|
| 48 | レイアウトを切り替えられる(札の「Layout」)。**desk**(既定): 2 枚のパネルを模型の左右に、机に広げた書類のように手前へ傾けて置き、時間割は手前の縁。**wall**: 模型の奥の壁(43) | ユーザーの希望は「机に展開」。どちらが読みやすいかは実機でしか決められないので、両方を残して比べる |
| 49 | **レンズ**(実験): ガラスの球。模型の上に持っていくと、球の真下の円の中だけ地面がデータのレイヤーに変わる(傾斜 / 分光)。手首をひねると種類が変わる。放すとその場に残り、模型の外で放すと元の場所へ戻る。札に、円の中心の傾斜の値が出る | アプリの名前そのものの操作。全体を塗り替えるボタンと違い、「見たい場所にかざす」ので、実画像を見ながら一部だけ調べられる(検討中だった 12 を採用)。最初から模型の右手前に置いてあり、何をするものか見れば分かる |
| 50 | **タイマー**(実験): 机の右手前のダイヤル。つかんで回すと計画の時間が進み、針がかかった作業が選ばれ、机の地図がその場所へ寄る | 時間割の区切りをタップする代わりに、時間を「回す」。宇宙飛行士の時計(ミッションタイマー)のモチーフ |
| 51 | 滑らせた地図は、放したあと少し流れて止まる | 手で動かす地図に重さを感じさせる |
| 52 | 公式パノラマの画素が無い部分は、周囲の画像をなだらかに混ぜた色で埋め(データ加工の段階で作る)、くすませて暗く描く。真下は 1 色へ寄せる | 以前は地形モデルの格子が透けていて、穴に見えた。埋めた部分は観測ではないので、画像と同じ鮮やかさにはしない。手首パネルにそう書く(32 の後半を置き換え) |
| 53 | 「Tools」で 49・50 を消せる。ボタンでの操作(Slope / Spectral、時間割のタップ)は残してある | 実験なので、無くても全部の操作ができるようにしておく |

**不具合の記録**: 46 の手のモデルは、関節を動かす部品を「動いているオブジェクト」に後付けしたため初期化に失敗し、手を認識するたびに例外を投げ続けていた。Quest ではその例外で、パススルーの層が毎フレーム提出されなくなっていた(ログで、合成の層が 2 から 1 に減っている)。「手が変わらない」と「真っ暗」は同じ原因。部品をオブジェクトを止めた状態で組み立てるように直し、Editor で 26 関節が結び付くことを確認した。実機では未確認。
