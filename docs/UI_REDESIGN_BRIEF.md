MissionLens(Unity / Quest 3)の UI を、見た目の方向性から作り直したい。提出後の作業。
今の UI は「AI が作った感じ」に見える。原因は、よくある SF 風テンプレートの見た目と、ルールのない文字サイズ・余白、文章の多さ。

## 方向性(決定済み)
- デス・ストランディングの UI を「考え方」の参考にする。
  抑えた配色、細い線、余白、ラベルと数字のメリハリ、必要な場面で地形や景色の上に情報を出すこと。
- フォント、アイコン、特徴的な記号など、ゲーム固有の形は真似しない。NASA の課題の提出物として、独自の見た目にする。
- 主役は白〜明るいグレー。シアンは「選べる / 選んでいる」ものだけに使う。
  色は MLPanel.cs の定数(Ink / Gray / Dim / Cyan / Amber / Soft / Back / Line)にある。
- 四隅のカギ型の飾り、シアンの格子の床、濃紺の半透明パネルはやめる方向。区切りは細い線と余白でつくる。

## 現状(別セッションで確認済み)
- UI は MLPanel(MLPanel.cs)の上に、ピクセル座標を直接指定して組んでいる。
  配置は主に MLAppPanels.cs、MLAppTools.cs、MLAppTable.cs、MLAppMenu.cs、MLAppFx.cs。
- .Text() の文字サイズは約 27 種類。余白やボタンの大きさは数字の直書き。
  先に「文字サイズの整理と文章の削減」をやっていたら、その結果を土台にする。
- 画面の参考: demo/frames/full_ja/。設計の経緯: docs/UI_DECISIONS.md。

## 進め方(各段階の終わりで止まって、私の承認を待つ)
### 段階 1: デザインのルールを提案する(コードはまだ変えない)
- 決めるもの: 文字(5〜6 段階: サイズ・太さ・色)、余白の刻み、色(役割ごと)、線の太さ、角の丸み、動き(出方・切り替え・押したときの反応)。
- 色について、決めた上で案を出してほしいこと:
  - 経路の色。今は青〜シアンなので「シアン = 操作できるもの」とぶつかる。
  - 出どころの区別(NASA の観測 / NASA の記録 / こちらの計算 / 模擬 / 仮想)を、色以外も含めてどう表すか。
  - 傾斜の黄・オレンジ・赤はデータの意味なので変えない。それとの共存も考える。
- 主要な 2〜3 画面(ブリーフィングの壁、机上の模型、現地の帯)の見た目の案を、画像で見せる。
  Editor のスクリーンショットでも、別に描いたモックでもよい。

### 段階 2: ルールをコードにする
- 段階 1 のルールを MLPanel に定数・部品としてまとめる。
- 部品の例: 見出し、本文、ラベル、ボタン(主 / 副)、出どころのラベル、区切り線、数字の表示。
- 画面のコードからは、この部品だけを使うようにする。

### 段階 3: 画面を作り直す
- 対象: タイトル、ブリーフィングの壁、時間割、机上の模型の周り(ラベル・マーカー・縮尺の表示)、
  現地の帯、手首パネル、メニュー、タイマー、振り返り。
- 各画面で主役(その場面の判断に使う 1 つ)を決め、文章を削り、注記は弱くする。
- 床・背景・パネルの形など、空間の見た目も合わせて変える。
- tools/unity_check.sh を通し、全画面の変更前と変更後のスクリーンショットを並べて報告する。

### 段階 4: 実機での確認
- Quest 3 での読みやすさ・ちらつき・フレームレートは、私が実機で確かめる。
- 確認してほしい点のリストを作り、私の所見をもとに直す。

## 守ること
- 出どころの区別は消さない。弱めるのはよいが、見れば区別できる状態を保つ(docs/UI_DECISIONS.md の「設計の軸」と #11)。
- 文字サイズは Quest での見かけの角度から決めてある(docs/UI_DECISIONS.md の冒頭と #43)。今の最小サイズより小さくしない。
- 英語と日本語の両方の表示で確認する。
- 判断したことは docs/UI_DECISIONS.md に追記する。
- コミットは私が指示するまでしないこと。
